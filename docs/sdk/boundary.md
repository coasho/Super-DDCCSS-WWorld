# The SDK's principals

Every entry point of the SDK - the C++ classes and functions and the C functions the DLLs export, the Python
SDK's functions and members - belongs to one principal of [ADR-31](../agent-boundary.md). The table below is
read from the DLLs and the Python package themselves (`tools/boundary/boundary.py`), so it cannot leave one out:
ctest's `sdk_boundary` fails on an entry point no rule classifies, and on this page when it is out of date.

An agent holds its own objects - fsim::Agent, fsim.Agent, an agent's C handle ([agents.md](agents.md)) - never
the range's World or Vehicle, and the library refuses an agent's handle every call that is not an agent's: each
C function an fsim_world* reaches opens with its guard, which `sdk_boundary` checks against this classification.
A **leak** is an agent's call that reaches what ADR-31 keeps from agents; those still open are counted below.

## Leaks

| Leak | What | Calls |
| --- | --- | ---: |
| L1 | Returns the World or the Vehicle: whoever holds an agent-facing object reaches every range call - closed for agents by AB-2a: an agent holds its own objects and handle, which refuse it | 0 |
| L2 | Identity declared by the caller: a Source or a ControllerId it chooses (a policy may claim Override) - closed for agents by AB-2a: an agent holds its own objects and handle, which refuse it | 0 |
| L3 | Truth labels in a report: a detection's or a track's `truth`, the entity behind it - closed for agents by AB-2a: an agent holds its own objects and handle, which refuse it | 0 |
| L4 | Another aircraft named by entity id - a strike's, a behaviour's or a must-fly point's target, a frame following a vehicle - and flown on its true state - closed for agents by AB-2a: an agent holds its own objects and handle, which refuse it; it names its own designations - targets by track, flown on their estimates (AB-2b) | 0 |
| L5 | Own ship as a whole VehicleState: sensor effects applied, but with fields no platform reports (crashed, diverged, step count) - closed for agents by AB-2a: an agent holds its own objects and handle, which refuse it | 0 |
| L6 | Messages: the sender is the caller's to set, and any node's inbox is readable - closed for agents by AB-2a: an agent holds its own objects and handle, which refuse it; by AB-4a its messages go through its system's DMS, named by SystemID - no entity id in what it sends or receives | 0 |
| L11 | World-global mission data: operational points, zones, lines, volumes and frames one agent writes are every agent's - closed by AB-2c: each MA's own, or the range's common, by owner | 0 |
