# C ABI

`#include <fsim/fsim_c.h>` - the binding surface for any language with a C
FFI (Rust `bindgen`, C#, Julia, Go, ...). The platform's own Python SDK
([python.md](python.md)) is built on it.

Rules: opaque handles, plain structs with a leading `struct_size` (call the
`*_init` function, then override fields), buffers and strings owned by the
library, integer return codes (`FSIM_OK` = 0, negative = error, text in
`fsim_last_error()`), no exceptions, no C++ types. Struct layouts only grow
within a major ABI version (`fsim_abi_version()`).

`examples/rust_trainer` is a complete Rust client (no bindgen): `src/ffi.rs` mirrors the structs, `src/main.rs` runs the object model and a VecEnv batch.

The equipment report additions (1.75) append report kinds 8-11 and the sized/bounded
`fsim_agent_strike_report_get` and `fsim_agent_consent_report_get` value reads. Existing report kinds 0-7, structs,
signatures and legacy equipment/consent calls are unchanged. See [Agent equipment access](engagement.md#agent-equipment-access-and-reports).
`FSIM_STORE_LOST` names the existing native store state 7; C and Python now return `"lost"` rather than an empty
status name. Existing store-state values 0-6 and invalid-value behavior beyond the defined enum remain unchanged.

Mission episodes (1.76, M5 core) are a header of their own, `fsim/fsim_mission_env.h`: three opaque handle kinds -
`fsim_mission_episode` (the range's: `_create` from an `ma.config.v1` document, `_reset`, `_step`, `_destroy`, and
`fsim_mission_endpoint_open` / `fsim_mission_referee_open`), `fsim_mission_endpoint` (an actor's: `_submit`,
`_observation_json`, `_receipts_json`, `_destroy`) and `fsim_mission_referee` (`_outcome_json`, `_truth_json`,
`_destroy`). A live handle of another kind is `FSIM_NOT_ALLOWED`; a malformed document, an unconfigured service, an
episode not reset or a handle of an earlier generation or ended episode `FSIM_INVALID_ARGUMENT`; a call that finds
another holding the episode `FSIM_ERROR`. Documents in are a pointer and a byte count; documents out are the two-call
read - a null buffer or capacity 0 reports the size with its terminator, a smaller capacity writes nothing - and no
read consumes anything. Nothing in `fsim_c.h` changed. See [mission-training.md](mission-training.md), sections 3 to 5.

Batches (1.77, M7 core) add a fourth handle kind to the same header, `fsim_mission_batch` (the range's): `_create`
from `count` configurations (pointer and byte count each) and `fsim_mission_batch_options` (`_init`: `NEXT_STEP`
autoreset, one worker, first local episode index 0), `_size`, `_reset`, `_reset_slot`, `_step`, `_status`
(`fsim_mission_slot_status`: generation, local episode index, tick, `FSIM_MISSION_SLOT_EPISODE_DONE`, `_ENDED` and
`_RESET` flags; read where the caller's `struct_size` has them), `_endpoint_open` and `_referee_open` (the ordinary
handles of a slot's current generation), the two-call `_final_observation_json`, `_final_outcome_json`,
`_final_truth_json` and `_final_costs_json`, `_remove_platform` and `_destroy`. Also additive:
`fsim_mission_episode_remove_platform` (`*removed` 1 when the platform was still there) and the referee's
`fsim_mission_referee_costs_json` (`ma.costs.v1`). Errors are the episode family's; a duplicate `env_id`, no
configuration, an unknown autoreset mode or zero workers is `FSIM_INVALID_ARGUMENT`, and so is a step before the
first reset. See [mission-training.md](mission-training.md), section 18.

## World and vehicles

```c
fsim_world_options wo; fsim_world_options_init(&wo);
wo.name = "rust-trainer";
wo.terrain = 1;                       /* optional: real relief; wo.record_path = "run.fsrec" records for --replay */
fsim_world* world; if (fsim_world_create(&wo, &world) != FSIM_OK) { puts(fsim_last_error()); return 1; }

fsim_vehicle_spec spec; fsim_vehicle_spec_init(&spec);
spec.name = "red-1"; spec.type = "jsbsim:f16"; spec.altitude_msl_m = 3000; spec.airspeed_ms = 200;
uint32_t red; fsim_world_create_vehicle(world, &spec, &red);

fsim_attitude_command att = {0.3, 0.05, fsim_hold(), 0.785, fsim_hold(), 200.0};
fsim_vehicle_command_attitude(world, red, &att);

for (int k = 0; k < 3000; ++k) {
    fsim_world_step(world, 1);
    const fsim_vehicle_state* s = fsim_vehicle_state_ptr(world, red);   /* valid until removal, updated per step */
    /* s->altitude_msl_m, s->euler_rad[0..2], s->velocity_ned_ms[...] ... same layout as fsim::VehicleState */
}
fsim_world_destroy(world);
```
