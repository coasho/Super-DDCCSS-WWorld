## 3. HC-49: do not bridge missing GPU query samples (P3, nonblocking)

In `src/visualization/render/GpuTimer.cpp`, `frameDone()` leaves `lastEnd_` intact when a query result is unavailable.
The next successful read subtracts that older endpoint, although one or more entire frames intervened. It labels
that interval as the gap before the new frame and also includes it in `maxGap_`, overstating unmarked time.

A scratch probe compiles the actual current `GpuTimer.cpp` against a query-return stub, without Vulkan execution:

| Result sequence | Frame timestamps (ms) | Actual adjacent gap before C | Reported gap before C / maximum |
| --- | --- | --- | --- |
| A success, B unavailable, C success | A: 100/101/105; B: 106/107/111; C: 112/114/118 | 1 ms | 7 / 7 ms |
| All three successful | Same timestamps | 1 ms | 1 / 1 ms |

The extra 6 ms includes B's marked rendering, not just a gap. This is a defect in the new diagnostic, not proof
of a simulation or rendering-behavior regression. The current Viewer waits the reused frame's fence and reads
queries three frames back, so normal submissions should already have results. No evidence establishes that a
skipped query affected the saved HC-45 run. Invalidate adjacency after unavailable/failed/invalid samples, or retain identities and calculate gaps
only between consecutive valid frames; report unavailable intervals honestly. Add a fast regression for the
skipped-query case and valid controls, including report boundaries. No GUI/full suite is needed to prove this fix.

Probe source, stub, output and exact commands: `D:/ENV/tmp/hc45-review/probe.cpp`, `vsg/all.h`, `probe.log`,
`commands.txt`. The compiler returned success with no output; no `compile.log` was produced.
