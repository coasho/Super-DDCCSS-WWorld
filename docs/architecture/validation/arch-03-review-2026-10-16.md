## 1. P2 / HC-12: required compiler include-path narrowing was not implemented

The [roadmap's ARCH-03 task 5](../migration/roadmap.md) explicitly requires
retaining target names/aliases and narrowing compiler include paths one target
at a time. The [implementation record, section 2](arch-03-foundation-and-leaves.md#2-policy-gate-and-selector)
states that narrowing was not done.

The moved targets still export the shared `${CMAKE_SOURCE_DIR}/src` root, for
example `src/foundation/core/CMakeLists.txt:23`,
`src/foundation/transport/CMakeLists.txt:16` and
`src/simulation/mission_systems/CMakeLists.txt:52`. This leaves private headers
outside their declared dependency closure visible to the compiler. The source
checker still rejects forbidden dependencies, but that is a different gate
from the planned compiler include visibility.

This is an uncompleted task, not a newly introduced simulation fault. Recording
it as an undecided later option does not complete the authorized ARCH-03 scope.

Required correction:

- Narrow the moved targets' private include exposure to their own headers and
  declared providers, one target at a time; adapt internal include spelling or
  build include organization as needed.
- Preserve target names, aliases, installed public header paths, registration,
  public ABI and runtime behavior.
- Add small compile-level positive/negative fixtures showing permitted includes
  work and an unrelated private module's headers are unavailable through the
  target's include environment.
- Update the target/include evidence and HC-12, run relevant fast checks and
  stop for acceptance. Do not start ARCH-04 or run a full suite while fixing it.
