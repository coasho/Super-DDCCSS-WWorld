## Original findings at 6c0de98

## 1. P2: unscanned public include fragments hide forbidden dependencies

Locations: `tools/architecture/check.py:532` and `622-623`.

The public inventory scans only `SOURCE_SUFFIXES`, excluding common include
fragments such as `.inc`, `.ipp` and `.tpp`. Include resolution can still find
such a file under `include/fsim`, but the public-edge loop silently skips an
unclassified target. Neither its ownership nor its contents are checked.

An isolated fixture demonstrates the resulting false acceptance:

```text
src/session/Header.h:           #include "fsim/Bridge.inc"
include/fsim/Bridge.inc:        #include "fsim/VecEnv.h"
include/fsim/VecEnv.h:          classified as training facade

issues: []
Bridge.inc classified: false
```

The equivalent classified `Bridge.h` produces `forbidden-public`, as expected.
`cmake/Install.cmake:65` installs the entire `include/fsim` directory, so the
unexamined include file is also a shipped input. This can conceal the exact
simulation-to-training or contract-to-domain dependency ARCH-02 is intended
to reject. The current tree does not contain this planted dependency.

Required correction: classify and scan public include targets independently
of their filename suffix, or explicitly reject unsupported public include
forms/files. An unclassified resolved public include must not disappear from
the acceptance analysis. Add focused negative fixtures for the indirect
simulation-to-training and contract-to-domain cases, with a valid include
control. Preserve the current three exact public exceptions.
