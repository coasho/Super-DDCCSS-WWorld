## 2. Enforced rules

The checker guide's ARCH-01 section ([tools/architecture/README.md](../../../tools/architecture/README.md)) gives
the details. In short:

- Every module has a domain and a kind (contract, implementation, final assembly, application). Direction rules
  hold on direct links and on includes of another module's header. The three current reverse edges are exact
  exceptions that name the package removing them. A stale exception fails.
- Ownership extends to the destination directories by longest prefix, and planned owners reserve their directories.
  A file in a domain root outside every destination has no owner. Equal claims fail as `duplicate-owner`, and a
  source listed by two targets fails as `duplicate-source`.
- Every allowance must be an actual link (`unused-allowance`).
- Python modules are checked for cycles with deferred edges included, facade backedges from private packages,
  optional eager imports, unregistered dynamic imports and undeclared subpackages.
- The policy is validated before any source is read. An unsupported or inconsistent declaration is an input
  error.

## 4. Reconciliation with the configured build

The procedure is defined in the checker guide (Reconciling with the configured build). The source parser stays the
ownership authority. Per required preset, the CMake File API code model must agree with it: configured targets are
registered modules, configured sources have the same owner, configured dependencies are source edges, and a source
edge is missing only where its branch is disabled. This runs in the exclusive build slot once source moves begin.
ARCH-01 configured nothing.
