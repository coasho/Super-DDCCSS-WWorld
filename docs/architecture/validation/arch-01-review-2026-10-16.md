## 1. P2: exact file claims bypass destination ownership

Locations: `tools/architecture/check.py:183-188` and `253-270`.

Policy validation checks an explicit `files` claim for a safe source path, but
does not enforce its domain or a reserved destination owner. `owner()` returns
the exact claim before consulting destination and planned-owner rules.

Isolated native fixture:

1. Create `src/training/native/mission/Takeover.cpp`.
2. Add that path to `modules.session.files`.
3. Add it with `target_sources(fsim_session PRIVATE
   ../training/native/mission/Takeover.cpp)`.

Without step 2, the checker correctly reports `planned-owner` for mission,
ARCH-05. With it, the CLI exits 0 and assigns the file to the simulation
`session` module. It reports neither a planned-owner nor a domain violation.

Required correction: retain explicit ownership for the existing legacy shared
directories, while rejecting claims that override another domain's destination
or a reserved module. Add a focused negative fixture.

## 2. P2: standard dynamic-import aliases escape registration

Location: `tools/architecture/python_imports.py:127-132`.

The scanner recognizes attribute calls named `import_module` and bare
`__import__`, but misses ordinary imported function names:

```python
from importlib import import_module
def load(name):
    return import_module(name)
```

The corresponding `from importlib import import_module as load_module` form
also yields an empty dynamic-import list. Both therefore bypass the required
site registration during a routine import-style refactor.

Required correction: recognize supported import-function bindings and aliases,
or fail explicitly on unsupported forms. Add registered and unregistered
negative/positive fixtures for both forms.

## 3. P2: parent-package initialization is missing from eager imports

Locations: `tools/architecture/python_imports.py:101-125` and `248-262`.

Minimal isolated package:

```text
fsim/__init__.py:                 from ._training.batch import run
fsim/_training/__init__.py:       import torch
fsim/_training/batch.py:          def run(): pass
```

The checker accepts this and reports the eager closure as only `fsim` and
`fsim._training.batch`. A real import using a tiny stand-in `torch` module
confirms that `_training/__init__.py` executes and imports the optional package.
The ordinary `import fsim._training.batch` form also omits the parent edge.

Required correction: account for imported ancestor-package initialization in
the eager-load analysis. Distinguish those initialization dependencies from
explicit facade imports so the fix does not create artificial facade cycles.
Add a regression in which an intermediate initializer loads an optional package.

## 4. P2: a stale exception between separate cycles is accepted

Location: `tools/architecture/python_imports.py:236-245`.

The checker flattens all cyclic strongly connected components into one member
set. It then accepts an exception when both endpoints appear anywhere in that
set, even if they belong to different cycles and the edge closes no cycle.

An isolated graph with deferred edges `a <-> c`, `b <-> d`, and one-way
`a -> b`, with exceptions `c -> a`, `d -> b`, and `a -> b`, returns no issues.
Its recorded cyclic components are separately `[a, c]` and `[b, d]`; the last
exception is stale and should fail.

Required correction: require the exception edge to participate in a cycle
(for example, its target must reach its source). Add a two-component regression.

## 5. P2: extension inputs and links are missing from the package baseline

Location: `tools/architecture/baseline.py:70-77`.
Existing build declarations: `python/CMakeLists.txt:71` and `80`.

The recorder extracts each extension's helper arguments and `target_sources`,
but misses the helper-added shared `src/fsim_py.h` and the stable-ABI
`${FSIM_PYTHON3_DLL}` link. It also ignores direct extension
`target_link_libraries` additions. The committed baseline omits those inputs.

An isolated recorder-function probe reports:

```text
recorded_sources: ["src/_native.c"]
recorded_links: ["fsim::sdk"]
header_change_invisible: true
link_change_invisible: true
```

The package-output record remains identical after a shared-header change or
helper/direct link change. This limits its usefulness as ARCH-01's exact
package-input/link baseline for subsequent compatibility-preserving moves.

Required correction: capture the helper-added inputs and actual declared
extension links, with explicit handling of unresolved/static-only declarations.
Add a focused mutation regression and regenerate the baseline.
