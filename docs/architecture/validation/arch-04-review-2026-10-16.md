## 2. HC-15 placement decision and explicit P022 adjustment

The original P022 assigned `src/sdk/Scenario.cpp` to `simulation_api` in
ARCH-04. That row was not completed as originally written; this review
explicitly revises it instead of describing the wrapper as already moved.

Decision: retain `fsim::applyScenario` as a thin public compatibility adapter in
the final SDK assembly, and relocate that file to
`src/adapters/sdk/cpp/Scenario.cpp` with ARCH-07. The path map, roadmap and
extraction design are updated accordingly. HC-15 remains open as this scheduled
relocation, with its decision resolved; it no longer blocks ARCH-04.

Rationale:

- Its fifteen-line implementation delegates scenario execution to the native
  runtime and converts vehicle identities to public handles. It owns no
  scenario parsing, physical state or independent simulation algorithm.
- Native scenario execution and its recipe already moved into simulation.
  Mission episodes use that native path; the lower mission facade does not
  need this public wrapper. Its example consumer links the final SDK.
- The existing public `Scenario.h` also declares training's `vecEnvOptions`.
  Keeping the compatibility adapter at the outer assembly avoids adding a
  simulation-to-training public-header exception merely to force a file move.
- This placement fits the accepted adapter boundary for public compatibility
  wrappers and preserves public paths, signatures, exports and behavior.

ARCH-07 must preserve that thin delegation, single definition and public
compatibility while moving the file. This decision authorizes no additional
domain exception, runtime duplication or implementation in the final assembly.
