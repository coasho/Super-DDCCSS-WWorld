## 2. HC-28: queued single-step requests are lost (P2)

`src/contracts/world_stream/DemoControl.h:25` specifies one step per increment
of `stepRequests`. In `src/applications/demo/main.cpp:187-188`, the publisher
marks all observed increments as seen while forwarding them to
`SimRunner::singleStep()`. That existing method sets one boolean latch
(`src/simulation/flight/SimRunner.h:41`), consumed once by the simulation loop
(`src/simulation/flight/SimRunner.cpp:49`). Multiple forwarded requests before
that consumption collapse into one step.

An independent process probe against the current executable queues 20 requests
while paused: **requested 20, completed 1**, with `dt=0.01` and a two-second
observation window. The control sends three requests one at a time and waits
after each: **requested 3, completed 3**, followed by a clean stop. This uses the
actual `DemoLink` object, publisher executable and shared-memory transport.

The current `demo_publisher` test requests one step and waits before requesting
the next, so its passing 240-step comparison cannot detect this loss.

Closure owner: Claude's ARCH-08 publisher/control package. Keep pending counts
until the corresponding steps complete, or forward only one outstanding step
at a time. Preserve existing simulation timestep, native latch semantics and
the read-only world stream. Add a regression for accumulated requests, retain
the one-at-a-time/parity controls, and verify pause/stop with pending work.

## 3. HC-29: failed startup leaks a Windows process handle (P3)

`src/applications/viewer/DemoLink.cpp:97-110` marks the child not running when
`GetExitCodeProcess` observes its exit, but leaves `info.hProcess` open.
`finish()` returns immediately when `running` is false (`:114-115`), so the
destructor also skips cleanup after a child exits before publishing a world.

The probe launches three real children with an invalid option. Each launch
fails as expected; the parent's process handle count rises **69 to 72**. The
current Viewer exits after this startup failure, so operating-system teardown
limits the immediate impact. This is a separate cleanup defect, not a second
phase blocker or the broader HC-27 placement decision.

Closure owner: the ARCH-08 `DemoLink` owner. Close every acquired process handle
regardless of the child's running state, and cover repeated failed startup
with a focused negative test and normal-start/stop control.

### HC-28 remains open: silence is not a completion acknowledgment (P2)

`src/applications/demo/main.cpp:246` treats a quiet interval of at least 100 ms
and 1.5 paced periods as proof the paused runner has settled. There is no bound
on how long an already-started ordinary step or a descheduled thread may take.
When that old step finally publishes, `SingleSteps::update()` at `:82-85`
credits its snapshot to the newly handed request.

A deterministic C++ probe extracts `SingleSteps` verbatim and models only the
unchanged runner's boolean latch and publication. The finite schedule is:

1. An ordinary running step remains in flight when pause and two requests arrive.
2. After 101 ms of silence the publisher hands request 1 to the latch.
3. The old ordinary step completes; before the runner next consumes the latch,
   the publisher mistakes that snapshot for request 1's completion and hands
   request 2 into the still-set boolean latch.
4. Only one requested step executes; both counter entries are considered taken.

The valid settled control completes **2/2**. The delayed schedule completes
**1 requested step for 2 requests**, plus the old ordinary step; the probe exits
1 as expected for a failing regression. This is a **controlled-interleaving
model, not an executed production publisher or measured heavy-flight failure**.
It demonstrates the acknowledgment flaw without a timing/load lottery.

Closure requires a deterministic hold/completion acknowledgment or another
mechanism that distinguishes old work from requested work; increasing a quiet
timeout does not establish that distinction. Preserve native timestep and
existing simulation behavior. Add the delayed-work schedule alongside the
settled burst/parity controls. Also strengthen the post-resume single-step
assertion at `tests/integration/test_demo_publisher.cpp:231`: `stepped > after`
plus no later snapshot cannot prove exactly one step when snapshots coalesce;
assert the exact agent-step time increment.

### HC-30: running/resume cancellation is not accepted (P2)

The existing assignment requires preserved behavior and pending-request
