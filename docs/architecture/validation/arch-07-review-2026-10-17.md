## 3. HC-22: explicit compatibility decision

**Accepted for this planned public-value split.** `VecEnv.h` retains its public
class signatures, opaque handle type and installation path, while mixed C/C++
source includes `fsim/fsim_c.h` explicitly to call C functions. The architecture
contract freezes names/signatures/layouts and installation headers, but does
not promise the complete C ABI transitively through the VecEnv header. This
decision is limited to that documented inclusion change; it is not a general
waiver of source or binary compatibility.

The independent syntax-only probe uses the previous header and current public
headers, with identical source calling `fsim_vecenv_reset(env.handle(), 0)`:

| Header use | Compile result |
| --- | --- |
| Previous `VecEnv.h`, no explicit C header | Exit 0 |
| Current `VecEnv.h`, no explicit C header | Exit 1: C function undeclared |
| Current headers with explicit `fsim/fsim_c.h` | Exit 0 |

Thus old binaries and unchanged signatures do not establish that every old
source file compiles unchanged. The narrower source contract is explicit in
`docs/sdk/vecenv.md` and is accepted here rather than mislabeled as complete
source parity. Probe: `build/architecture-reviews/arch07-ebd3a09/header_probe.py`
and `header_probe.json`. No product target was rebuilt for it.
