## 1. Scope and non-goals

Deliver the complete vertical **SIM-M04 (MS-8)** feature across native C++, C99 ABI, Python SDK, native 6-DOF JSBSim flyout envelope generation for all 24 maintained air-to-air missiles, explicit propagated uncertainty, published-performance comparison, installed-package staging, boundary classification, and regressions.

- **Sole simulation authority:** JSBSim remains the sole native 6-DOF flight integrator. Flyout tables (`aircraft/stores/<model>/<model>.dlz-v1.json`) are generated directly from native JSBSim missile flyouts using each store's actual XML, propulsion, VLM aerodynamics, finite-fin autopilot/allocator/actuator chain, battery life, arming time, and seeker constraints.
- **No parameter fitting to published figures:** Published card `range_km` values are validation comparison targets only, never inputs or drag/thrust fit objectives. Current aerodynamic/motor models remain explicitly `equipment_calibrated: false` (`basis: "simulated"`).
- **Zero ABI breaks & strict permission boundaries:**
  - `fsim::ms::LaunchZone`, `fsim_launch_zone`, `World::launchZone`, `Agent::launchZone`, `fsim_world_launch_zone`, `world.launch_zone`, and `agent.launch_zone` preserve exact struct layouts, signatures, legacy fallback for unknown/empty/non-AAM stores, and Agent own-designation restrictions.
  - Rich DLZ/WEZ outputs (R_max, R_ne, R_min, R_pi, TOF, F-pole, A-pole, uncertainty bounds, envelope/range flags, provenance, and aspect WEZ contours) are added via versioned interfaces (`LaunchZoneV2`, `LaunchZoneWezV1`, C99 `fsim_launch_zone_v2` / `fsim_launch_zone_wez_v1`, Python `launch_zone_v2` / `launch_zone_wez`).
  - Agent calls strictly require an own-platform designation; true entity IDs, foreign designations, and lapsed designations are refused identically to legacy `launchZone`.

## 2. Open-source evaluation

- **Evaluated alternatives:**
  1. External 3-DOF / point-mass DLZ estimators (e.g., RocketPy point-mass trajectory scripts, textbook Breguet/energy approximations, MIXR `IMissile` robot-aircraft DLZ stubs): none reproduces this SDK's actual 6-DOF JSBSim VLM aerodynamic tables, solid/dual-pulse/ducted-rocket propulsion curves, finite-fin incidence/rate limits, or loft/PN guidance coupling.
  2. Synchronous runtime 6-DOF JSBSim bisection inside `World::launchZone`: physically exact but ~0.2–1.0 s per query and incompatible with real-time 4v4 / HUD / DRL stepping budgets (< 50 us/query).
- **Selected solution:** Reuse the vendored LGPL-2.1 **JSBSim** flight integrator through a dedicated offline/build-time native 6-DOF flyout generator (`fsim-dlz-generator`, linking `fsim::session`) to produce deterministic, hash-bound `.dlz-v1.json` envelope tables for all 24 AAMs, paired with a zero-allocation deterministic 5-D multilinear + off-boresight turn-loss runtime evaluator (`src/simulation/mission_systems/weapon/LaunchZone.{h,cpp}`).

## 3. Frozen operating envelope, predicates, and uncertainty

- **5-D Flyout Grid (540 grid points per AAM):**
  - Launch altitude $h_L \in \{1000, 6000, 12000\}\text{ m}$ (ISA)
  - Launch Mach $M_L \in \{0.6, 0.9, 1.2, 1.5\}$
  - Target altitude delta $\Delta h = h_T - h_L \in \{-3000, 0, +3000\}\text{ m}$ ($h_T = \max(500\text{ m}, h_L + \Delta h)$)
  - Target Mach $M_T \in \{0.6, 0.9, 1.2\}$
  - Target aspect angle $\psi_A \in \{0^\circ\text{ (head-on)}, 45^\circ, 90^\circ\text{ (beam)}, 135^\circ, 180^\circ\text{ (tail-chase)}\}$
- **Off-Boresight Turn-Loss Curve:**
  - Flyout-derived kinematic factor $\eta_{\text{ATA}}(\theta)$ evaluated at $\theta \in \{0^\circ, 15^\circ, 30^\circ, 45^\circ, 60^\circ\}$ (bounded by card `seeker_gimbal_deg` / `launch_fov_deg`).
- **Native 6-DOF Flyout Predicates (`dt = 1/120 s`, `frameSkip = 4`):**
  - **Intercept:** Released native JSBSim missile (with actual card `fuze_arming_s`, `guidance_life_s`, `guidance_max_g`, `loft`, propulsion, VLM aero, finite-fin autopilot) achieves swept CPA $\le \max(25\text{ m}, 2 R_{\text{fuze}})$ at $t \in [t_{\text{arm}}, t_{\text{life}}]$ without ground impact/divergence, with terminal speed $\ge \max(120\text{ m/s}, 0.85 V_T)$.
  - **$R_{\max}$ ($R_{\text{aero}}$):** Maximum launch slant range achieving intercept against a constant-velocity non-maneuvering target at $(h_T, M_T, \psi_A)$, solved by bisection to $\le \max(100\text{ m}, 0.5\% R)$.
  - **$R_{\text{NE}}$ ($R_{\text{tr}}$, No-Escape):** Maximum launch slant range achieving intercept when the target executes an immediate $7 g$ sustained level break turn at $t = 0^+$ onto the pure tail-away ($180^\circ$) escape heading at $M_T$, solved by bisection ($0 \le R_{\text{NE}} \le R_{\max}$).
  - **$R_{\min}$:** Minimum launch slant range achieving an armed intercept ($t_{\text{CPA}} \ge t_{\text{arm}}$), solved by bisection ($0 \le R_{\min} \le R_{\text{NE}}$ when launchable).
- **Explicit Propagated Uncertainty:**
  - Perturbed native JSBSim flyouts on anchor grid points using conservative engineering model uncertainty bounds ($\pm 10\%$ propulsion / thrust scaling or card impulse uncertainty, $\pm 15\%$ VLM drag scaling per SIM-M02 uncalibrated VLM disclosure, $\pm 5\%$ battery life), yielding explicit fractional 1-sigma bounds $(\delta_{R_{\max}}, \delta_{R_{\text{NE}}}, \delta_{R_{\min}}, \delta_{\text{TOF}})$ propagated into every runtime query.
- **Published-Performance Comparison:**
  - All 24 AAMs compared at high-altitude head-on ($12\text{ km}, M_L = 1.5, M_T = 0.9, 0^\circ$) and medium-altitude head-on ($6\text{ km}, M_L = 0.9, M_T = 0.9, 0^\circ$) against card `range_km` in `docs/research/sim-m04/dlz-published-comparison.json` and `docs/research/sim-m04/dlz-published-comparison.md`.

## 5. Verification gates

1. Unit & mathematical tests (`launch_zone_core`): 5-D multilinear interpolation exactness at knots, strict ordering $0 \le R_{\min} \le R_{\text{NE}} \le R_{\max}$, out-of-envelope clamping/flagging, off-boresight attenuation, F-pole/A-pole/TOF closed-form checks, uncertainty positivity, corrupted-table rejection.
2. Native 6-DOF JSBSim cross-check (`launch_zone_native`): actual released JSBSim missile launched inside $R_{\text{NE}}$ and $R_{\max}$ vs outside $R_{\max}$ confirms physical consistency with the generated `.dlz-v1.json` envelope across active radar (AIM-120C), semi-active (AIM-7M), and infrared (AIM-9M/AIM-9X) families, plus deterministic identical results across worker counts.
3. All 24 AAM `.dlz-v1.json` generation & published-performance comparison audit.
4. C++, C99 ABI (`c_abi`, `ma_equipment`, `ma_equipment_c`), Python (`test_engagement.py`, `test_ma_equipment.py`), `sdk_boundary`, and installed `equipment_package_consumer` on both `ucrt64-headless` and `ucrt64-release` presets.
