# Synchronous native tank inertia at the published CG

The SDK mass transaction must publish a tank inertia tensor about the same CG as its empty-body and point-mass terms. The ordinary native step remains unchanged. This versioned synchronous path uses one native mass-balance execution and a frozen set of current tank inputs.

The pinned native sequence supplied `CalculateTankInertias()` before `FGMassBalance::Run` calculated a new CG. Tank inertia therefore used the preceding CG; the remaining terms used the newly calculated CG. An empty second mass-balance call could change all nine tensor entries. This differs from exact-zero velocity setter reconstruction: the setter-only guards already restore the original World-reset case, while the independent tensor case remains a separate failure.

For each frozen tank in native authored order, the synchronous path retains current pounds w, current fill-dependent structural location x in inches, and native intrinsic moments. After native CG c is calculated, it uses the unchanged native conversion r=((c_x−x_x),(x_y−c_y),(c_z−x_z))/12 feet, mass m=w/32.174049 slugs, and native `GetPointmassInertia` for m[(r·r)I−rrᵀ]. Each tank contribution and its three intrinsic moments are accumulated in the exact order of the native tank loop. No aggregate tensor translation or analytic rounding correction supplies the production tensor.

`FGMassBalance::RunWithInputRefreshV1` is an additive nonvirtual method in the generated shadow header. It executes the original native operation body once, with one optional borrowed callback after CG calculation and before CG tracking, ground displacement and the original inertia/inverse composition. It retains the original scheduling and Holding guards, pre-functions, mass/CG calculations, ground operation, tensor/inverse arithmetic, post-functions and return. The existing virtual `Run` delegates with null callback; no instance member, virtual slot or public SDK layout changes. The callback must not re-enter/advance the model, change mass/CG inputs or retain context. Only inertia inputs may be refreshed about the computed CG.

The adapter snapshots actual tank values before that one run; its total weight and moment use the native per-accumulator authored order. Its input tensor is first initialized at the old CG to retain the pre-function input phase. The same immutable rows then supply the canonical new-CG tensor inside the native run. Post-functions therefore see the corrected tensor at the original native point; no refresh occurs after post-functions and no pre/post/ground phase is repeated. If native hooks intentionally mutate raw mass properties during the run, the published derived values describe the run's frozen tank input batch and native one-pass point/base inputs, rather than a speculative second run. Concurrent model mutation remains outside the existing single-owner model contract.

This repair closes tank-reference coherence. Existing gas tensor inputs and native mated-child treatment pass through unchanged; they are not newly claimed to be coherent about the changed CG. A separate gas-cell or child-FDM domain needs its own input snapshot/ownership validation. No gas or child behavior is silently refused, reconstructed, advanced or advertised as completed here.

All generated JSBSim changes originate in `cmake/JsbsimPatches.cmake`; vendored and build-generated products are never hand-edited. The additive shadow header is used consistently by newly compiled library, object and adapter consumers. Unchanged `FGFDMExec.cpp` is generated beside it because the vendor source's relative quoted `models/FGMassBalance.h` would otherwise bypass include precedence. The header and relocated source accompany the existing patch-source distribution. Old-header binaries keep the original virtual Run symbol, layout and vtable; compatibility acceptance still requires normal installed-consumer gates.

The original World reset has 17 unchanged predicates. The exact-zero transaction test retains all 78 scalar bit comparisons. The independent tank-reference test uses long-double parallel-axis arithmetic and separately checks whole-tensor change attribution; its numerical bounds belong only to the independently reordered reference, not the exact identity contract. Method controls compare ordinary Run with explicit null refresh, Holding callback suppression, and exactly one refresh at the newly calculated CG before tensor composition. Native validation status belongs to the dated evidence receipt; source equivalence is not a native or ABI acceptance result.

The committed-end regression begins before changing one actual native tank input and independently checks the final tank tensor and public rigid-mass tensor after endMassChange. It complements the unchanged intermediate tensor and exact-zero identity probes; its unit-only mass mutation does not change authored models or encounter scenes.

The coherence guarantee is limited to SDK synchronous `JsbsimModel::runMassBalance` transactions. Ordinary executive `FGMassBalance::Run` retains the accepted native one-pass input timing; this patch does not repair or claim complete inertia-epoch coherence for ordinary flight integration.
